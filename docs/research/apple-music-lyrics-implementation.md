# Apple Music 歌词开发验证

> 1.2.2 发布版暂时关闭此实验的编译及设置入口，旧偏好不会触发后台读取或联网。以下为此前开发过程的验证记录。

## 实现

- `AppleMusicLyricsMonitor.swift`：独立开关；音乐应用运行时每 0.6 秒读取 Apple Events 歌曲元数据和进度，0.1 秒本地选句。暂停冻结插值，拖动由下一次样本重新校准，失去样本后不无限推进。
- `LRCLyrics.swift`：多时间标签、全局 offset、空白歌词区间、逐字标签清理、二分选句；候选匹配校验歌名、艺人／专辑和时长，拒绝歧义时间轴。
- LRCLIB `/api/get` 优先；无同步歌词时 `/api/search` 补充。成功结果按歌曲标识及元数据的 SHA-256 缓存到 `~/Library/Caches/<bundle-id>/Lyrics/`。歌词缓存无需上传。
- 歌曲变更、禁用和读取失败会取消旧任务；异步结果通过 generation 校验，避免旧歌覆盖新歌。未匹配的结果不永久写入磁盘。
- 新增 Apple Events 使用说明及自动化 entitlement；不嵌入特权令牌、不调用苹果非公开歌词接口，不引入模型或第三方依赖。
- 菜单栏、普通面板和灵动岛复用现有显示组件；Apple Music 正在播放时优先显示其歌词，暂停时结合当前来源选择。

## 自动检查

```sh
swiftc space_playbar/LRCLyrics.swift Tests/LRCLyricsTests.swift -o /tmp/cueto-lrc-tests
/tmp/cueto-lrc-tests
```

覆盖多时间标签、正负 offset、空白区间、时间排序、倒退 seek、同时间标签，以及候选时长、专辑版本、艺人别名、歧义时间轴的选择。

## 已观察到

- Debug 构建通过；歌曲读取获得授权。
- Apple Music 的 Wicked Games 显示艺人为 Abel Tesfaye，专辑为 The Highlights (Deluxe)，时长约 325 秒。LRCLIB 相应记录使用 The Weeknd。
- 默认精确查询没有同步结果；加入别名、保守版本匹配后返回带时间戳的歌词。
- Cueto 设置实际显示歌词，短暂播放期间可观察到换句，暂停后恢复暂停状态。
- 本地缓存文件生成；开发版签名包含 Apple Events entitlement。
- UI 工具设置音乐滑块的操作未改变实际进度，没有据此认定 seek 通过。随后用户手动测试并确认“拖动后能正确返回”，因此手动 seek 对齐验收通过。
- 用户保持播放并切到没有音乐窗口的另一个桌面，确认歌词“持续换句，正常”；跨桌面验收通过。
- Release 构建及签名完整性校验通过，签名包含 Apple Events entitlement，且不包含 get-task-allow 调试权限。

## 网络故障恢复

- 2026-10-27 在 Cueto Dev 内记录到 `/api/get` 返回 HTTP 503，随后 `/api/search` 返回 200；设置面板已恢复显示当前歌曲歌词。失败发生在第三方歌词请求阶段。
- 精确请求失败后也尝试搜索，并继续使用原有歌名、艺人、时长和歧义校验；搜索未匹配且精确请求失败时保留错误，避免误报成曲库缺失。
- 网络失败最多尝试三轮，轮次间等待 2／6 秒；禁用、手动重试及切歌会取消旧任务。请求超时改为 20 秒，并绕过 URL 缓存以避免重复使用失败响应。
- 设置区分 HTTP 状态码、超时、网络和响应格式错误。统一日志仅记录接口路径、状态、字节数和错误，不记录歌词、歌曲信息或完整查询 URL。
- `Tests/LyricsHTTPClientTests.swift` 使用模拟响应验证 200、404、503、超时和请求缓存策略；Debug 构建通过。

## 后台恢复与提前准备

- 三轮短重试仍失败后，播放期间按 30／60／120／300 秒间隔继续恢复，后续保持 300 秒上限；确实无匹配时每 300 秒重新检查。成功及切歌重置调度，暂停时不触发新的定时恢复。
- 网络可用及系统唤醒会提前唤醒已等待的恢复；已有请求不会并发重复启动。
- 每 15 秒尝试读取顺序播放列表的一个后续候选，只在关闭随机播放、索引遵循播放顺序且当前索引的 persistent ID 校验一致时使用。不修改 Music 的播放设置或队列，不发送切歌命令。
- Apple Events 没有完整待播队列接口，手动队列排序、自动播放和流媒体播放上下文可能无法提前确认。候选只用于预取；实际切歌后严格核对完整歌曲 key 才使用，不能把候选当作当前歌曲。
- 只保留一个准备结果；预取等待当前歌词请求完成，不做失败重试，不新增持久化缓存策略。
- `Tests/LyricsRecoveryScheduleTests.swift` 验证退避上限、网络恢复、重置及无匹配等待；Debug 构建通过。开发版已重启，真实队列预取命中与网络中断恢复仍需实机场景验收，调度测试不代替这些验收。
- 实机日志观察到失败后的后台请求再次发生。测试中另发现 Dancing In The Flames 搜索结果有一条 `duration: null`，原先导致整批解码失败；已允许空元数据解码并在匹配阶段拒绝未知时长，保留其他有效候选，回归测试通过。重启后该搜索请求返回 200，面板状态为“没有找到同步歌词”，而非网络或格式错误；未据此宣称该曲歌词已匹配。

## 边界

这不是 Apple Music 官方歌词，覆盖率和时间精度取决于 LRCLIB。未承诺所有曲库、现场版、翻唱版和纯音乐都能匹配。未发布版本、未修改版本号。
