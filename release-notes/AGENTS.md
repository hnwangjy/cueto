# 更新说明写作规范

- 使用正式、简洁的产品语言，参考 Apple 产品介绍与软件更新说明的表达方式。
- 应用内更新说明使用简短的无序列表，每条说明一项体验变化。直接写清操作方式、可感知的改进或适用场景，无需在列表前加概述或宣传语。
- 采用简短、自然的句子，减少“现在可以”“先……再……”“更好看了”等口语表达。避免夸张宣传、空泛修饰和开发过程叙述。
- 功能介绍兼顾清晰与节奏感。修复说明客观描述受影响的场景和修复结果，所有表述须与实际发布内容一致。
- 应用内提供简体中文与英文版本，保持含义与语气一致。
- GitHub 更新说明按“新增”“修复”“删除”逐项列出实际变更，每条聚焦一项变化。
- 安装说明沿用现有简洁格式，不展示 SHA，也不添加此前已要求移除的签名与公证说明。
